01
INSPECT

먼저, 서비스의 현재를 읽습니다.

웹서버와 실제 PHP 환경, CMS 종류와 문자셋을 확인하고 기준 URL 응답을 수집합니다.

  • .git·DB 덤프·백업 파일의 HTTP 노출 확인
  • 업로드 디렉토리의 PHP 실행 가능성 점검
  • 의심 파일, PHP 설정과 구버전 라이브러리 탐지
analyze → scan → plan.tsv
02
COMPATIBILITY

바꿀 코드와 남길 코드를 구분합니다.

PHP 토큰을 분석해 자동으로 변환 가능한 문법과 수동 검토가 필요한 부분을 나눕니다.

변환 전
$letter = $text{0};
변환 후
$letter = $text[0];
  • 짧은 태그, 중괄호 인덱스와 PHP4 생성자 등 변환
  • mysql_* 등 제거된 함수의 런타임 호환 레이어
  • 현재·목표 PHP 문법 검사와 수동 확인 목록
03
VERIFY & RECOVER

적용 후에도 확인은 계속됩니다.

변경 파일, 기준 응답, 데이터 비교 결과를 기록해 적용 결과를 검토할 수 있게 합니다.

자동화의 범위를 먼저 확인하세요

PHP 업그레이드 자체, CMS 이전, 모든 비즈니스 기능의 호환성 검증까지 자동으로 처리하지는 않습니다. 생성된 계획과 수동 조치 목록을 검토해야 합니다.
